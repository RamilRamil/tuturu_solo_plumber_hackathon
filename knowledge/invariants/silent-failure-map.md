# Принцип

Главная особенность архитектуры: она по умолчанию **врёт молча, а не падает**.
По линзе *Failure and cost of error* каждый узел с катастрофическим радиусом
(порча данных, тихий неверный результат, ранжирование по ложной цене) обязан
иметь митигацию в дизайне. Её отсутствие — верхняя находка в вердикте.

# Невидимые глазами отказы (проверять в первую очередь)

| Отказ | Проявление | Митигация-инвариант |
|---|---|---|
| Мисрезолв города | билеты в город-омоним с ценами | [guard-before-price](guard-before-price.md) |
| Маппинг ингредиент→теги | выдача правдоподобна и неверна | «качество маппинга и есть продукт», не строка конфига |
| Привязка POI к узлу | билеты не в тот город | [sellability-is-edge](sellability-is-edge.md) |
| Per-mode soft-fail | цена занижена/завышена, ранжирование врёт | сверять `modes_requested` с `modes_summary`, логировать |
| Частичная выгрузка OSM | слой тихо неполон = «такого нет» | карта покрытия данных (V4), штриховка регионов без данных |
| Цена отеля | двойной счёт | `stay_total`, не умножать на `nights` |
| Электричка 0 ₽ | ложная «бесплатность» | нулевую цену считать отсутствием |
| Устаревший кэш | карта и чекаут расходятся | отметка времени, жюри проверит первой |

# Как использую

Это не отдельный инвариант, а **линза**: при ревью любого воркера прохожу его
выход по этой таблице и спрашиваю «если этот шаг тихо ошибётся — есть ли митигация
в коде, или отказ уйдёт в демо незамеченным?». Код-нитпики сюда не входят —
для них `best-practices-review`.
