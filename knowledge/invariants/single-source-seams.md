# Инвариант

Четыре шва между потоками существуют **в единственном экземпляре**:
1. **Схема БД** — единственный источник моделей. Никто не определяет свои —
   только импорт. Особо: `leg` (B2), три исхода (B1).
2. **Контракт API** (`/api/places`, `/api/price` SSE) — заморожен, меняется
   только через архитектора, с уведомлением фронта.
3. **MCP-клиент** — один модуль `lib/tutu_mcp.py`, используют A и C.
4. **Guard §7** — там же, в MCP-клиенте, не копировать в два места.

# Почему нерушимо

A/B/C/D работают параллельно на фикстурах. Любой продублированный шов
разъедется при первой же правке: две реализации guard дадут разное поведение
на мисрезолве, две модели `leg` — рассогласование серых карточек. Это классическая
утечка границы: одно и то же понятие в двух представлениях без явной трансляции.

# Что считать нарушением

- Воркер определяет собственную модель данных вместо импорта из схемы.
- Второй парсер ответа Tutu или второй guard.
- Фронт и бэк разошлись в форме события SSE, потому что контракт не был заморожен.

# Как проверяю

Grep по определениям моделей/парсеров в потоках A/B/C. Единственность
`tutu_mcp.py`. Ссылки [guard-before-price](guard-before-price.md),
[sellability-is-edge](sellability-is-edge.md).
