# Гейт готовности к часу 0

Раскладка слепых зон из анализа плана на две корзины: **что должно быть «зелёным»
до первой строки кода** и **что закрываем по ходу с назначенным владельцем и
дедлайном**. Плюс третья — то, что сознательно **не** чиним (принятый риск).

Принцип сортировки: в час 0 идёт то, что либо (а) общий контракт/интерфейс между
потоками, либо (б) единая точка отказа, либо (в) дёшево сейчас и дорого на 30-м
часу, либо (г) ломается тихо. Всё остальное — на ходу.

Тип метки: **[РЕШЕНИЕ]** — договориться, **[ПРОВЕРКА]** — измерить/убедиться,
**[АРТЕФАКТ]** — написать файл.

## A. Блокирует час 0 (зелёное до кода)

### G1. Схема БД заморожена  [АРТЕФАКТ] · арх
- **Что:** `schema.sql` + модели: `leg` (B2), `probe_status ∈ {sellable,not_sellable,misresolved}` (B1), поля стабильного `cluster_id`, `poi/hub/cluster/route_cache/hotel_cache/misresolve_log`.
- **Почему час 0:** общий интерфейс A/B/C; расхождение схемы = переделка у всех.
- **Зелено:** файл есть, A/B/C импортируют модели, свои не заводят.
- **Красное:** все 4 потока стоят. Единая точка отказа — делать первым.

### G2. Контракт API заморожен, включая `cluster_id`  [АРТЕФАКТ+РЕШЕНИЕ] · арх
- **Что:** `plans/api-contract.md`: `/api/places`, `/api/price` SSE, payload каждого события. **Отдельно — формат и детерминированность `cluster_id`** (стабилен между радиусами и между фазами, иначе рвётся фаза1→фаза2 и шеринг).
- **Почему час 0:** интерфейс B↔D и B↔C. Меняется — переделывает фронт.
- **Зелено:** D генерит моки по контракту без вопросов; C принимает `cluster_id` от B по правилу, а не по совпадению.
- **Красное:** фронт и фаза 2 разъезжаются, всплывёт на интеграции.

### G3. Guard для узлов вне `cities_ru.json` + канонический источник региона  [РЕШЕНИЕ] · арх+A
- **Что:** (1) как guard'ить **продаваемый узел, найденный в OSM, которого реально нет в `cities_ru.json`** — в справочнике 1134 города, ингест D3 находит POI/узлы за его пределами; откуда тогда `expected_region`. (2) какой источник региона канонический при расхождении — `subject` из cities_ru против OSM `admin_level=4`.
- **НЕ про эталон (исправлено):** Ростов Великий **в справочнике есть** — запись `«Ростов» / Ярославская область` (проверено на `data/cities_ru.json`). `expected_region` доступен; отказ эталона — это имя запроса («Ростов» → Ростов-на-Дону), уже покрытое алиасами B1. Не якорить час 0 на несуществующей проблеме и не заводить лишний механизм источника региона ради эталона.
- **Почему час 0:** задаёт поведение guard в общем случае, а guard — единая точка, пишется в час 0 (G4).
- **Зелено:** для узла вне справочника определён источник `expected_region` (напр. OSM `admin_level=4`) и guard проходит на фикстуре такого узла.
- **Красное:** узлы за пределами 1134 городов либо тихо отбрасываются, либо проходят без проверки региона.

### G4. MCP-клиент + guard как единый модуль  [АРТЕФАКТ] · арх
- **Что:** `lib/tutu_mcp.py`: initialize, POST /mcp, парсер json+SSE, семафор concurrency, тайм-аут ≥30 с, **guard §7 здесь же**.
- **Почему час 0:** и A, и C зависят; guard — единая точка тихого отказа (пропустит мисрезолв или отбросит валидное). Две реализации = два разных бага.
- **Зелено:** guard красный на фикстуре «Ростов»→Ростов-на-Дону, зелёный на «Ростов Великий».
- **Красное:** тихая ложь с ценами или тихое исчезновение города — в обоих потоках сразу.

### G5. Замер concurrency Tutu + план Б  [ПРОВЕРКА] · A
- **Что:** 30-мин проверка 1/2/4/8 параллельных. **И заранее решить, что делаем, если реально <4**: какие волны/окна режем, чтобы D2 всё равно успел.
- **Почему час 0:** все бюджеты времени (V1/V3, ~2,7 ч на матрицу) держатся на этом числе. Узнаём в час 0 — а ветку «мало» надо иметь готовой, не изобретать на 20-м часу.
- **Зелено:** число записано в orchestration §6; ветка «<4» описана.
- **Красное:** матрица D2 не успевает, обнаружится поздно.

### G6. SSE проходит прокси без буферизации  [ПРОВЕРКА] · арх/C
- **Что:** сквозной smoke-тест: тестовый SSE-эндпоинт через тот же nginx/прокси VPS, что и прод. Убедиться, что события идут по одному, а не пачкой в конце.
- **Почему час 0:** nginx буферизует SSE по умолчанию — вся фаза 2 «работает», но стриминг мёртв. Тихий отказ, дорогой на 40-м часу. Проверка стоит 10 минут сейчас.
- **Зелено:** три события приходят с задержкой между ними, а не разом.
- **Красное:** весь UX «результаты по мере готовности» — фикция.

### G7. pyosmium ставится и парсит региональный pbf  [ПРОВЕРКА] · A
- **Что:** из open-issues: проверить установку из PyPI и парсинг одного регионального `.osm.pbf` за приемлемое время — **до** скачивания 4 ГБ `russia-latest`.
- **Почему час 0:** если pyosmium/память не тянут, вся стратегия D3 меняется, а 4 ГБ качать впустую — потеря часов.
- **Зелено:** Ярославская область распарсена, счётчики сходятся с field-test §12.
- **Красное:** стратегия ингеста POI пересматривается.

### G8. Скелет репо + решения по стеку  [РЕШЕНИЕ+АРТЕФАКТ] · арх+орк
- **Что, одним пакетом:** (1) **B и C — один FastAPI-сервис или два** (порты/структура); (2) язык/версии фронта, пакетный менеджер; (3) `docker-compose` для локалки; (4) git-стратегия (ветки, кто мержит); (5) **механизм передачи `.db` от VPS(A) к бэку(B/C)** — общий том / scp / коммит артефакта.
- **Почему час 0:** это механика совместной работы. Решается за час, рефакторится сутки.
- **Зелено:** четверо клонируют, поднимают локалку, знают куда коммитить.
- **Красное:** потоки наступают друг на друга, БД не доезжает до бэка.

### G9. Золотые фикстуры  [АРТЕФАКТ] · арх
- **Что:** `fixtures/` — ответы Tutu для «Ростов»/«Ростов Великий»/«Великий Новгород» (из G5-проверки), выборка POI по Ярославской обл., несколько `leg`, ответ отеля. Формат = ровно то, что MCP-lib кладёт в БД. Плюс данные под **эталон №1 и запасной бургер**.
- **Почему час 0:** это подмена, которая разблокирует B/C/D до готовности ингеста. Без неё параллельности нет.
- **Зелено:** B/C/D стартуют без сети и без реальных данных A.
- **Красное:** три потока ждут ингест — параллельность схлопывается в последовательность.

### G10. Ранний интеграционный чекпоинт назначен  [РЕШЕНИЕ] · орк
- **Что:** вписать в таймлайн сборку A+B+C+D **раньше часа 44** (кандидат: конец часа 26 — первый сквозной проход /places→/price на реальных данных волны 1).
- **Почему час 0:** сейчас потоки сходятся впервые за 4 часа до конца — big-bang интеграция. Это решение таймлайна, принимается до старта, даже если исполнение позже.
- **Зелено:** в orchestration §3 стоит чекпоинт с владельцем и критерием.
- **Красное:** интеграционные баги вскрываются, когда времени на них нет.

## C. Сознательно не чиним (принятый риск)

- **R1. Дрейф цены день-в-день** ломает жёсткое «4 342 ₽». Принимаем: регресс ±15%, кэш-фолбэк с пометкой времени. Не гоняем живой замер на каждый прогон.
- **R2. Неполное покрытие POI по стране** (успеваем 268 городов графа, не всю РФ). Принимаем: карта покрытия штриховкой (V4) — честная дыра как этап.
- **R3. `checkout_url` может протухнуть на демо.** Частично митигируем перегенерацией перед выступлением; глубокого решения в 001 нет.
- **R4. Запасной одноузловой бургер живьём не проверен** (в отличие от эталона №1). Принимаем до 30-мин проверки; если будет окно в G5 — снять живой ответ и добавить в фикстуры.

## Порядок закрытия корзины A (единая точка отказа)

Гейты образуют DAG с зависимостями. **Параллельность только после критических путей.**

```
G1 (схема БД)
  ├─ G2 (контракт API на схеме)
  │  ├─ G3 (решение источника региона для общего случая)
  │  └─ G4 (MCP-lib; использует G3)
  │     └─ G9 (фикстуры, требуют MCP-lib)
  │
  ├─ G8 (скелет репо — не блокирует, но раньше лучше)
  │
  └─ параллельно (VPS, слабо связано):
     ├─ G5 (замер concurrency + ветка <4)
     ├─ G7 (pyosmium)
     └─ G6 (SSE-smoke через прокси; требует G8)
  
  G10 (ранний интеграционный чекпоинт — правка в таймлайн, артефакт)
```

**Ключевой путь:** G1 → G2 → G3 → G4 → G9 (всё сериал, зависимости крепкие).
**Параллель:** G5, G7, G6 стартуют после G1 + G8.
**Красный на любом гейте** — весь старт встаёт (не обходить).

## Как пользоваться

1. Раздать архитектору + рабочему A **один промпт** с явной структурой по ролям и
   последовательностью (см. ниже в этой сессии).
2. Архитектор идёт последовательно: G1 → G2+G3 → G4 → G9; параллельно готовит
   G8 и G6. Рабочий A независимо: G5 (замер) + G7 (pyosmium).
3. G10 — текстовая правка в `plans/00-orchestration.md` §3 (вписать чекпоинт).
4. Красный гейт — оркестратор стоп, не пускает в код.

## Что НЕ начинать, пока корзина A не 10/10 🟢

- Кластеризацию (B, worker-B)
- `/api/places`, `/api/price` (B, C)
- Фронт (D, worker-D)
- Живой ингест (A, worker-A, даже если результаты нужны)

Всё зависит от гейтов. Если на 10-м часу выяснится, что G4 красный, переписывать
кластеризацию было зря.
