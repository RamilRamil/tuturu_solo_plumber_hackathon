# План: Рабочий A — Ингест данных (VPS)

Ты добываешь все данные. Живёшь в `ingest/`, запускаешься на VPS (настоящая сеть).
Твой поток самый долгий — начинай раньше всех, крутись фоном. Всё кэшируй в БД
**до** обработки: повторный прогон не должен снова дёргать API.

Читать: `data-collection-spec.md` (целиком), `ingredients.yaml`,
`open-issues.md` B1/B2/V1, `tutu-mcp-field-test.md`.
Зависишь от: схема БД + `lib/tutu_mcp.py` (Архитектор, час 0–2).

## D1 — Реестр продаваемых узлов (час 3–10, БЛОКЕР для B/C/A4)

`ingest/probe_hubs.py`. Проба: `search_multitransport(origin="Москва",
destination=<город>, departure_date=<будний, +3–4 недели>, adults=1, page_size=1)`.

**Три исхода (B1), ретрай не отказ:**
- Порядок попыток имени: алиас из `data/city_aliases.json` → имя как есть →
  «имя, субъект» одной строкой.
- Guard §7 (из MCP-lib): регион `meta.to.region` vs `subject` из cities_ru.json,
  вхождение подстроки с нормализацией. Расхождение → следующий вариант имени.
- Исчерпали варианты с мисрезолвом → `MISRESOLVED` (не схлопывать в NOT_SELLABLE!).
- Продаваемость читать по `meta.modes_summary` и `meta.unavailable`, НЕ по числу
  вариантов. Все режимы пусты → `NOT_SELLABLE`, но узел **не удалять** (режим
  «своим ходом»). Правила записи — таблица в data-collection §D1.
- Каждый мисрезолв → строка в `misresolve_log`.

Создать `data/city_aliases.json`. Стартовый набор — из open-issues B1 + омонимы V5
(22 имени). Ключ `"Ростов|Ярославская область": ["Ростов Великий", ...]`.

Волны: (1) 268 городов ≤400 км от Москвы — сортировать по полю `dM` (V6, без
геометрии); (2) города >100 тыс. (175 шт.); (3) остальное. Волна 1 ≈ 4 мин.

**Регресс (B1 п.4):** после волны 1 в реестре обязаны быть Ярославль, Ростов
Великий, Рязань, Коломна, Тула, Калуга, Владимир, Иваново. Отсутствие = падение.

## D3 — POI из OSM (час 3–10, параллельно D1, БЛОКЕР для B)

`ingest/parse_osm.py`, `pyosmium`. Источник: Geofabrik `russia-latest.osm.pbf`
(~4 ГБ), парсинг локально. **Overpass не использовать** для массовой выгрузки.

- Теги/классы/плотность — из `ingredients.yaml`. Промтуризм переопределить
  (field-test §11): музеи техники/промышленности/горного дела/ж-д/военные +
  исторические шахты, НЕ `man_made=works`.
- Парсер `start_date` (грязный: `"after 1600"`, `"1725..1836"`, `"1801"`) →
  from/to. Значимость §9. Три состояния opening_hours (открыт/закрыт/неизвестно).
- Вытащить границы регионов `admin_level=4` → `expected_region` для guard + привязка.
- **Приоритет ингеста (V4):** сначала 268 городов графа, не «вся Россия».
  Один связный регион с полными данными сильнее десяти с дырами. Отдать карту
  покрытия (список залитых регионов) для фронта.

## D4 — Wikidata (час 10–16)

`ingest/enrich_wikidata.py`. SPARQL `query.wikidata.org/sparql`, разбивать по
классам и регионам (COUNT ~22 с). Матчинг: тег `wikidata` (4,4%) + по координатам
радиус ~100 м. `P571` для «древности». Классы — `ingredients.yaml:wikidata_classes`.

## D2 — Матрица перегонов (час 10–16, нужен D1)

`ingest/probe_legs.py`. Только пары **продаваемых** узлов ≤150 км, где **обе**
стороны дают POI по ингредиентам (самый сильный фильтр, бесплатный). Обе стороны
пары — разные вызовы (асимметрия: Тверь→Торжок ok, Торжок→Москва 0). Писать в `leg`.
Пересчитать бюджет сразу после D1 (доля продаваемых). Регресс — таблицы §D2.
