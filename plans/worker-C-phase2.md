# План: Рабочий C — Фаза 2 (живая, Tutu MCP, SSE)

Ты достраиваешь маршруты и цены после ввода origin. Всё через стриминг — синхронный
UX невозможен (латентность до 26,7 с). Дорогие вызовы только для топ-5 кластеров.

Читать: `mvp-spec.md` §4/§7/§10, `tutu-mcp-reference.md` §4–6, `open-issues.md`
B2/V3, `data-collection-spec.md` §D5.
Зависишь от: `lib/tutu_mcp.py` + guard (Архитектор, час 1–2), таблица `leg` (A4),
кэш (A/D5). На старте — фикстуры legs/hotel.

## `/api/price` по SSE (§4)

Вход `{cluster_id, origin, days, month, adults, children_ages[], budget_scope}`.
События по мере готовности:

| event | payload |
|---|---|
| `resolved` | что резолвилось + результат guard §7 |
| `leg` | from, to, mode, price, duration, checkout_ref |
| `hotel` | город, min_price, nights, checkout_ref |
| `breakdown` | транспорт / жильё / итого (обязательна) |
| `checkout` | готовые checkout_url по каждому плечу |
| `warning` | плечо не найдено, объект без часов и т.п. |
| `done` | финальный итог |

**Первый `leg` обязан прийти ~3 с, а не после всех** (иначе спиннер при готовых
данных). Порядок городов — система, по географии (переезд с вещами, ночёвка в
каждой точке).

## Guard §7 (из MCP-lib, не копировать)

Координат в ответах Tutu нет → сверять имя+регион. Расхождение по региону →
результат отбросить, `warning` + строка в misresolve_log, кластер/плечо пометить
недостижимым. Полное имя города передавать всегда. `also_named` не проверять — его нет.

## Плечи и перегоны (B2 — свойство ребра)

Продаваемость плеча — из таблицы `leg` (направленная пара), не из атрибута узла.
**Обратное плечо проверять отдельным вызовом для каждого города** (Торжок→Москва=0
при Тверь→Торжок ok; составные маршруты сервер не строит). Если из последнего
города возврата нет — предложить возврат из предыдущего.

Недостижимые после origin карточки **не исчезают — сереют с причиной** (§3).

## Окна дат — лениво (V3)

N дней в пределах месяца, проверять по одному окну в неделю. НЕ считать 140
вызовов синхронно: первое окно для топ-3 → показать → остальные догружать.
35 вызовов на топ-5 без окон; окна — по мере необходимости.

## Чекаут

`create_checkout_link` с полями из `checkout_ref`. URL воспроизводить **ровно**
как вернул сервер — непрозрачная строка, не пересобирать/не подрезать. Для avia
прокидывать `passengers_full/child/infant`, иначе сумма не сойдётся.

## Кэш и фолбэк

`route_cache`/`hotel_cache` — читать перед живым вызовом; они же фолбэк на
выступлении (отдать последние цены с пометкой времени). Прогрев делает A (D5).

## Ловушки

Цена отеля = `stay_total`, не за ночь — не умножать на nights. Per-mode soft-fail
молчит — сверять `modes_requested` с `modes_summary`, логировать. Электричка 0 ₽ =
отсутствие. Тайм-аут ≥30 с. Быстрый пустой ответ (0,1–0,8 с) = нет `*_id` у назначения.
