## Кластеризация §6 — диски вокруг узлов, НЕ DBSCAN

Пользователь понимает радиус как **диаметр набора**. DBSCAN на 100 км склеит
пол-страны. Алгоритм:

1. Кандидат кластера — один продаваемый узел **или пара** узлов на расстоянии
   ≤ `radius_km` (пары нерезаемы — решение B4).
2. POI кластера — объекты в радиусе `r_local` (дефолт 25 км) от любого узла.
3. Диаметр — **фактический**, по крайним объектам, вернуть в `diameter_km`.
   Может превысить `radius_km` до `2×r_local` — считать честно, показать в карточке.

Гаверсинус. Пары генерировать только среди узлов с `probe_status=sellable`
(флаг из A); непродаваемые тоже показывать, но с пометкой «своим ходом».

## Скоринг significance §9 (на уровне POI)

```
significance = 3*has_wikidata + 2*has_wikipedia + 2*has_start_date
             + 1*has_name + min(len(tags)/5, 2)
```
«Древний» = start_date_to < порог ИЛИ Wikidata P571 < порог. Одиночным признаком
ранжирования быть не может (wikidata 4,4%, heritage 0,2%).

## Ранжирование кластеров B3 (сортировка places[])

```
cluster_score =
      w1 * coverage_ratio            # доля ингредиентов бургера, покрытых
    + w2 * log(1 + Σ significance)   # суммарный вес POI кластера
    + w3 * rarity                    # 1 / число кластеров с той же комбинацией
    + w4 * log(1 + population)       # приор «есть что делать» (из cities_ru.json)
    - w5 * (diameter_km / radius)    # компактность
    - w6 * (0 если продаётся, 1 если «своим ходом»)
```
**`coverage_ratio` обязан доминировать:** кластер с обоими ингредиентами всегда
выше кластера с одним, независимо от остального. Реализовать как лексикографику:
сначала по числу покрытых ингредиентов, потом по score. Веса вынести в конфиг.
При равном coverage одиночный Ярославль (храм+музей) и пара эталона — оба
законные полные ответы; **не** калибровать веса, чтобы пара стала #1.
SC-ranking: пара в топ-5, не обязательно первое место. Храмы Ярославля в
фикстурах не вырезать. Регресс — живой проход дисков, таблица `cluster` пуста.

Счётчик редкости `rarity` = 1/число кластеров с той же комбинацией ингредиентов.
`coverage: {matched, missing}` в каждом кластере.
